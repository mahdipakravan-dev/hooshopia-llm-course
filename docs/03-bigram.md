# قسمت ۳: baseline با مدل bigram

قبل از ترنسفورمر، ساده‌ترین مدل ممکن رو می‌سازیم تا یه عدد مرجع داشته باشیم. هر مدلی که بعداً می‌سازیم باید از این بهتر باشه.

## مدل

`BigramLM` فقط یه جدول `V × V`ـه: سطر `i` امتیاز (logit) هر توکنیه که می‌تونه بعد از توکن `i` بیاد.
مدل فقط توکن فعلی رو می‌بینه و هیچ حافظه‌ای از قبلش نداره.

## داده به شکل بچ

`encode_corpus` همهٔ سندها رو پشت سر هم به یه دنبالهٔ بلند توکن تبدیل می‌کنه و بعد از هر سند `<|endoftext|>` می‌ذاره.
`get_batch` پنجره‌های تصادفی به طول `block_size` برمی‌داره؛ `y` همون `x`ـه که یه خونه جابه‌جا شده.
یعنی توی هر پنجره، مدل در هر موقعیت باید توکن بعدی رو حدس بزنه.

## تابع loss

```
loss = cross_entropy(logits, targets) = -log(احتمالی که مدل به توکن درست داده)
```

مدلی که هیچی نمی‌دونه به همهٔ توکن‌ها احتمال برابر `1/V` می‌ده؛ پس loss اولیه باید نزدیک `ln(V)` باشه.
اگه نبود، یه جای کار ایراد داره. این اولین چکِ سلامت هر آموزشه.

## حلقهٔ آموزش

```python
x, y = get_batch(train, batch_size, block_size)
_, loss = model(x, y)          # forward
opt.zero_grad()
loss.backward()                # گرادیان
opt.step()                     # به‌روزرسانی وزن‌ها با AdamW
```

همین چهار خط تا آخر دوره ثابت می‌مونه؛ فقط مدل و جزئیات (زمان‌بندی LR، دقت عددی، checkpoint) عوض می‌شن.

`estimate_loss` هر بار روی همون بچ‌های ثابت loss رو میانگین می‌گیره تا عددها قابل مقایسه باشن. loss روی `val` نشون می‌ده مدل واقعاً یاد گرفته یا فقط داده رو حفظ کرده.

## اجرا

```bash
python -m llm.data --input data/sample/raw --out data/clean
python -m llm.tokenizer train --data data/clean --vocab-size 1024 --out tokenizer.json
python -m llm.train_bigram --data data/clean --tokenizer tokenizer.json --steps 2000
```

خروجی متنیِ bigram بی‌معنیه، چون هر توکن فقط به توکن قبلش نگاه می‌کنه. قسمت بعد همین مشکل رو با attention حل می‌کنیم.
