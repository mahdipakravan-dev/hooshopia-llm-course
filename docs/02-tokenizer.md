# قسمت ۲: توکنایزر BPE از صفر

مدل متن نمی‌بینه؛ عدد می‌بینه. توکنایزر متن رو به دنباله‌ای از عددها (توکن) تبدیل می‌کنه و برعکس.

## چرا BPE بایت‌محور؟

- **از بایت شروع می‌کنیم:** ۲۵۶ مقدار بایت. هر متنی به هر زبانی همیشه قابل کدگذاریه؛ هیچ «کلمهٔ ناشناخته»‌ای نداریم.
- **ادغام جفت‌های پرتکرار:** پرتکرارترین جفت توکنِ کنار هم رو پیدا می‌کنیم و یه توکن جدید براش می‌سازیم. این کار رو تکرار می‌کنیم تا به اندازهٔ واژگان برسیم.
- **نتیجه:** کلمه‌های پرتکرار یه توکن می‌شن، کلمه‌های نادر چند تکه.

هر حرف فارسی توی UTF-8 دو بایته؛ برای همین بدون توکنایزرِ آموزش‌دیده روی فارسی، متن فارسی تقریباً دو برابر انگلیسی توکن می‌خوره.

## پیش‌توکن‌سازی

قبل از BPE متن رو به تکه‌ها می‌شکنیم (`PATTERN`): کلمه با فاصلهٔ قبلش، عدد (حداکثر ۳ رقم)، علامت‌ها، فاصله‌ها.
ادغام‌ها هیچ‌وقت از مرز تکه رد نمی‌شن. نیم‌فاصله جزو کلمه حساب می‌شه، پس `می‌خواهم` یه تکه‌ست.

## پیاده‌سازی سریع

نسخهٔ ساده بعد از هر ادغام همهٔ جفت‌ها رو از اول می‌شمره و روی دادهٔ واقعی خیلی کنده. `Tokenizer.train`:
- هر تکهٔ یکتا رو یک بار با تعدادش نگه می‌داره (نه کل متن رو)،
- شمارش جفت‌ها رو بعد از هر ادغام فقط برای کلمه‌هایی که عوض شدن به‌روز می‌کنه،
- بهترین جفت رو با heap پیدا می‌کنه.

تست `test_fast_training_matches_naive_reference` نشون می‌ده خروجیش دقیقاً با نسخهٔ ساده یکیه.

اگه هیچ جفتی دست‌کم دو بار تکرار نشه، آموزش زودتر تموم می‌شه؛ پس `vocab_size` واقعی ممکنه از عددی که خواستی کمتر باشه.

## توکن‌های ویژه

از همین حالا چهار توکن رزرو می‌کنیم: `<|endoftext|>` بین سندها، و `<|user|>`، `<|assistant|>`، `<|end|>` برای قالب چت در قسمت ۷.
این‌جوری برای SFT لازم نیست توکنایزر رو از اول بسازیم.

## اجرا

```bash
python -m llm.tokenizer train  --data data/clean --vocab-size 8192 --out tokenizer.json
python -m llm.tokenizer encode --tokenizer tokenizer.json "مدل زبانی توکن بعدی را پیش‌بینی می‌کند."
python -m llm.tokenizer stats  --tokenizer tokenizer.json --data data/clean
```

روی دادهٔ نمونه (فقط ۲۹ سند):

```
م | دل |  زبانی |  توکن |  بعد | ی |  را |  پیش‌بینی |  می‌کند | .
39 chars -> 10 tokens
```

روی کورپوس واقعی، `--vocab-size` بین ۸ تا ۳۲ هزار مناسبه. برای سرعت می‌شه با `--max-docs` روی بخشی از داده آموزش داد.
