# قسمت ۸: ارزیابی

تا اینجا فقط loss آموزش رو دیدیم. حالا دو سؤال: مدل روی متنی که ندیده چقدر خوبه؟ و به‌عنوان دستیار واقعاً به درد می‌خوره؟

## ۱. loss و perplexity روی val

```
perplexity = exp(loss)
```

perplexity تقریباً یعنی «مدل بین چند توکن مردده». مدل آموزش‌ندیده بین همهٔ توکن‌ها مردده، پس perplexity‌اش نزدیک اندازهٔ واژگانه.

`perplexity()` برخلاف ارزیابی وسط آموزش، کل داده رو با پنجره‌های پشت سر هم و بدون هم‌پوشانی می‌خونه؛ پس عدد قطعیه و هر بار یکی درمیاد.
این عدد فقط بین مدل‌هایی با **یک توکنایزر** قابل مقایسه‌ست؛ توکنایزر دیگه یعنی توکن‌های دیگه و loss دیگه.

## ۲. جواب به سؤال‌های ثابت

`evals/prompts.jsonl` چند سؤال ثابت داره که هر مدلی رو باهاش می‌سنجیم. جواب‌ها greedy (`temperature=0`) تولید می‌شن تا قابل تکرار باشن.
دو سؤال آخر عمداً بی‌جوابن («دیروز چه اتفاقی افتاد؟»): مدل خوب باید بگه نمی‌دونه، نه اینکه چیزی از خودش بسازه.

## خطاهای رایج مدل‌های کوچیک

| خطا | نشونه | راه حل |
|---|---|---|
| **تکرار** | یه جمله مدام تکرار می‌شه | temperature یا top-p بالاتر؛ دادهٔ بیشتر |
| **ساختن اطلاعات** | جواب مطمئن ولی غلط | مثال‌های «نمی‌دونم» توی دادهٔ SFT |
| **تموم نکردن** | `<|end|>` نمیاد و تا سقف توکن ادامه می‌ده | مثال‌های SFT بیشتر؛ چک کن `<|end|>` توی ماسک باشه |
| **overfit** | loss روی train پایین، روی val بالا | دادهٔ بیشتر، مدل کوچیک‌تر یا آموزش کوتاه‌تر |

## اجرا

```bash
python -m llm.evaluate \
    --ckpt checkpoints/small/ckpt.pt checkpoints/sft/ckpt.pt \
    --tokens data/tokens --prompts evals/prompts.jsonl --out reports/eval.md
```

گزارش (`reports/eval.md`) جدول loss و perplexity هر checkpoint و جواب‌هاشون به هر سؤال رو کنار هم نشون می‌ده؛ مثلاً مدل پیش‌آموزش در برابر مدل بعد از SFT.
