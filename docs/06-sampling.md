# قسمت ۶: تولید متن

مدل در هر قدم یه توزیع احتمال روی همهٔ توکن‌ها می‌ده. اینکه از این توزیع چطور انتخاب کنیم، کیفیت متن رو خیلی عوض می‌کنه.

## انتخاب توکن بعدی (`pick`)

| روش | کار | اثر |
|---|---|---|
| **greedy** (`temperature=0`) | همیشه محتمل‌ترین توکن | قطعی، ولی زود تکراری می‌شه |
| **temperature** | `logits / T` قبل از softmax | `T<1` توزیع رو تیزتر و محافظه‌کارتر می‌کنه، `T>1` پخش‌تر و خلاق‌تر (و پرت‌تر) |
| **top-k** | فقط k توکن محتمل‌تر | جلوی انتخاب توکن‌های خیلی بعید رو می‌گیره |
| **top-p** (nucleus) | کوچک‌ترین مجموعه‌ای که جمع احتمالش به p برسه | مثل top-k، ولی اندازهٔ مجموعه با اطمینان مدل تغییر می‌کنه |

ترتیب: اول temperature، بعد top-k، بعد top-p، بعد نمونه‌گیری.

## KV Cache

بدون cache، برای هر توکن جدید کل متن از اول از مدل رد می‌شه؛ یعنی کار برای توکن `n`ام از مرتبهٔ `n` و برای کل متن از مرتبهٔ `n²`ـه.
ولی `k` و `v` توکن‌های قبلی هیچ‌وقت عوض نمی‌شن (ماسک علّی). پس نگهشون می‌داریم:

```
prefill:  کل prompt یک بار از مدل رد می‌شه و k,v هر لایه ذخیره می‌شه
decode:   هر قدم فقط توکن جدید وارد می‌شه؛ k,v اش به cache اضافه می‌شه
```

تغییرات مدل (`llm/model.py`): `KVCache` و `LayerCache`؛ `forward(..., cache=)` جایگاه RoPE رو از `cache.seq_len` شروع می‌کنه.
تست‌ها نشون می‌دن خروجی با cache و بدون cache یکیه (`test_cached_logits_match_full_forward`، `test_greedy_same_with_and_without_cache`).

وقتی متن از `block_size` بلندتر بشه، cache رو با نیمهٔ آخر متن از نو می‌سازیم.

## اجرا

```bash
python -m llm.sample --ckpt checkpoints/small/ckpt.pt --prompt "هوش مصنوعی" --temperatures 0 0.7 1.3
python -m llm.sample --ckpt checkpoints/small/ckpt.pt --prompt "هوش مصنوعی" --bench
```

`--bench` سرعت تولید با و بدون cache رو مقایسه می‌کنه.

`stream` توکن‌ها رو یکی‌یکی برمی‌گردونه (`yield`)؛ همین تابع توی قسمت ۹ برای استریم جواب به مرورگر استفاده می‌شه.
